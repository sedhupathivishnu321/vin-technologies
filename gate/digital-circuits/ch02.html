2.1 Weighted and non-weighted codes

  • BCD: each decimal digit coded in 4 bits; 6 codes (1010–1111) are invalid. A BCD number takes more bits than pure binary.
  • Excess-3: BCD \(+3\); self-complementing (the 9’s complement is the bitwise complement); useful for decimal subtraction.
  • 2421 and 5211: weighted self-complementing codes.
  • Gray: successive values differ in exactly one bit (unit distance).

2.2 BCD addition

Add the digits as 4-bit binary numbers. If the result exceeds 9 (1001) or a carry is produced out of the digit, add \(0110_2\) (\(=6\)) to that digit and propagate the carry.

BCD sum

\(47+38\): \(0100\,0111+0011\,1000\). Low digit \(0111+1000=1111\) (15 \(>9\)) \(\Rightarrow\) add 0110: \(1\,0101\), digit 5, carry 1. High digit \(0100+0011+1=1000\) (8). Result \(1000\,0101=85\) \(\checkmark\).
\(9+8\): \(1001+1000=1\,0001\), carry set so add 6: \(0001+0110=0111\) with carry 1 \(\Rightarrow\ 0001\,0111=17\) \(\checkmark\).

2.3 Gray code

Binary \(\leftrightarrow\) Gray

Binary \(B_{n-1}\dots B_0\to\) Gray: \(G_{n-1}=B_{n-1},\quad G_i=B_{i+1}\oplus B_i\)  (i.e. \(G=B\oplus(B\gg1)\)).
Gray \(\to\) binary: \(B_{n-1}=G_{n-1},\quad B_i=B_{i+1}\oplus G_i\) (cascaded XOR from the MSB).

Reflected-Gray construction: write the \((n-1)\)-bit sequence, mirror it, prefix 0 to the first half and 1 to the second. Applications: rotary encoders, K-map labelling, glitch-free counters.

Solved Example

\(1011_2\to G\): \(1,\ 1\oplus0=1,\ 0\oplus1=1,\ 1\oplus1=0\Rightarrow 1110\). Back: \(B_3=1\), \(B_2=1\oplus1=0\), \(B_1=0\oplus1=1\), \(B_0=1\oplus0=1\Rightarrow1011\) \(\checkmark\). An \(n\)-bit Gray counter of \(2^n\) states makes exactly \(2^n\) single-bit transitions per cycle (the last state also differs from the first by one bit).

2.4 Alphanumeric codes

ASCII is a 7-bit code (\(128\) symbols): digits 0–9 are \(30_{16}\)–\(39_{16}\), uppercase A is \(41_{16}\), lowercase a is \(61_{16}\) (differ by \(20_{16}=32\)). Extended ASCII uses 8 bits; Unicode (UTF-8) is variable-length.

2.5 Error-detecting and error-correcting codes

2.5.1 Hamming distance

The Hamming distance \(d(x,y)\) is the number of bit positions in which two words differ. The minimum distance \(d_{\min}\) of a code decides its power:

Detection and correction capability

Detect up to \(\ d_{\min}-1\ \) errors.   Correct up to \(\ t=\left\lfloor\dfrac{d_{\min}-1}{2}\right\rfloor\ \) errors.
Detect \(e\) errors and correct \(t\) errors simultaneously: \(d_{\min}\ge e+t+1\) with \(e\ge t\).
Correct erasures: up to \(d_{\min}-1\).

2.5.2 Parity

A single parity bit makes the number of 1s even (even parity) or odd (odd parity). \(d_{\min}=2\): detects any odd number of errors, corrects none. A two-dimensional (row/column) parity array can locate and correct a single error. Parity generation: XOR of all bits.

2.5.3 Hamming code

For \(k\) data bits and \(r\) parity bits, single-error correction requires \[ 2^r\ge k+r+1. \] So \((7,4)\): \(r=3\); \((15,11)\): \(r=4\); \((31,26)\): \(r=5\). Parity bits sit at positions \(1,2,4,8,\dots\); parity bit \(p_{2^j}\) checks all positions whose binary index has bit \(j\) set. Adding one overall parity bit gives SECDED: \(d_{\min}=4\) (single-error correct, double-error detect).

(7,4) Hamming

Data \(d_1d_2d_3d_4=1011\) at positions \(3,5,6,7\).
\(p_1\) checks positions \(1,3,5,7\): \(p_1\oplus1\oplus0\oplus1=0\Rightarrow p_1=0\).
\(p_2\) checks \(2,3,6,7\): \(p_2\oplus1\oplus1\oplus1=0\Rightarrow p_2=1\).
\(p_4\) checks \(4,5,6,7\): \(p_4\oplus0\oplus1\oplus1=0\Rightarrow p_4=0\).
Codeword (positions 1–7): \(0\,1\,1\,0\,0\,1\,1\).
Suppose it is received as \(0110111\) (bit 5 flipped). Syndrome \(s_4s_2s_1\): \(s_1=0\oplus1\oplus1\oplus1=1\), \(s_2=1\oplus1\oplus1\oplus1=0\), \(s_4=0\oplus1\oplus1\oplus1=1\Rightarrow 101_2=5\): the error is at position 5. Flip it back.

2.5.4 Checksums and CRC

A cyclic redundancy check appends \(m\) bits, the remainder of the message (shifted left by \(m\)) divided modulo 2 by a generator polynomial of degree \(m\). The receiver divides the whole codeword; a non-zero remainder signals an error. CRC detects all burst errors of length \(\le m\).

CRC

Message \(1001\), generator \(x^3+x+1=1011\). Append three zeros: \(1001000\div1011\) (XOR long division) gives remainder \(110\), so the transmitted word is \(1001110\).
Message \(1101011011\) with generator \(10011\) (\(x^4+x+1\)) gives remainder \(1110\).

Conceptual Trap

(i) Hamming distance of a code is the minimum over all pairs, not the average. (ii) Even parity detects an odd number of bit errors only; two errors cancel. (iii) In BCD addition a digit result \(\ge10\) or a carry out both require the \(+6\) correction. (iv) Gray code is not a weighted code, so it cannot be added directly.

GATE Shortcut

Hamming \((n,k)\): \(n=2^r-1\) and \(k=n-r\). The syndrome, read as a binary number, is the error position (0 means no error). Self-complementing codes (excess-3, 2421) allow 9’s complement by plain inversion.

2.6 GATE problems

GATE 1-Mark Problems

Q1. Excess-3 code of decimal 6 is (A) 0110 (B) 1001 (C) 1000 (D) 0101.

Q2. A code has \(d_{\min}=5\). Which (detect \(e\), correct \(t\)) pair can it support simultaneously? (A) \(e=3,t=3\) (B) \(e=2,t=2\) (C) \(e=4,t=2\) (D) \(e=1,t=4\).

Q3. Gray code of binary \(0110\) is (A) 0101 (B) 0111 (C) 1010 (D) 0011.

Q4. The minimum number of parity bits in a Hamming code for 11 data bits is (A) 3 (B) 4 (C) 5 (D) 6.

Answers: Q1 (B): \(6+3=9=1001\). Q2 (B): need \(e+t+1\le5\) with \(e\ge t\); \(e=t=2\) works, (C) needs 7. Q3 (A): \(G_3=0\), \(G_2=0\oplus1=1\), \(G_1=1\oplus1=0\), \(G_0=1\oplus0=1\). Q4 (B): \(2^4=16\ge11+4+1\).

GATE 2-Mark Problems

Q5. BCD addition \(0111\,0101+0010\,0111\) (\(75+27\)) yields (A) 1000 0010 (B) 0001 0000 0010 (C) 0001 0000 0001 (D) 1010 1100.

Q6. A (7,4) Hamming code word received is \(1010101\) (positions 1–7 left to right, even parity). The bit position in error is (A) none (B) 3 (C) 5 (D) 7.

Q7. Message \(110\) is protected using CRC generator \(101\) (\(x^2+1\)). The transmitted codeword is (A) 11010 (B) 11011 (C) 11001 (D) 11000.

Answers: Q5 (B): \(75+27=102\). Low digit \(0101+0111=1100>9\), add 6: \(1\,0010\), digit 2, carry 1. High digit \(0111+0010+1=1010>9\), add 6: \(1\,0000\), digit 0, carry 1. Result \(0001\,0000\,0010\). Q6 (A): with bits \(1,0,1,0,1,0,1\) at positions \(1\ldots7\), \(s_1\) (positions 1,3,5,7) \(=0\), \(s_2\) (2,3,6,7) \(=0\), \(s_4\) (4,5,6,7) \(=0\): no error. Q7 (B): \(11000\div101\) (modulo-2) leaves remainder \(11\), so the word is \(11011\).

Numerical Answer Type (NAT)

Q8. Number of parity bits needed to single-error-correct 26 data bits: .

Q9. Minimum distance required to detect 3 errors and correct 1 error simultaneously: .

Q10. Total number of 8-bit words at Hamming distance exactly 2 from a given word: .

Answers: Q8: \(2^r\ge 26+r+1\); \(r=5\): \(32\ge32\) \(\checkmark\), so 5. Q9: \(d\ge3+1+1=5\). Q10: \(\binom82=28\).

Multiple Select (MSQ)

Q11. Which are true? (A) A single parity bit can correct a single-bit error. (B) Gray code is a unit-distance code. (C) Excess-3 is self-complementing. (D) BCD is a weighted code.

Answers: Q11: (B), (C), (D).

Chapter Test

T1. Add BCD \(38+45\).   T2. Hamming codeword for data \(0110\) (even parity, positions 1–7)?   T3. \(d_{\min}=6\): detect? correct?

Answers: T1: low \(8+5=13>9\), add 6 gives digit 3 with carry; high \(3+4+1=8\); result \(1000\,0011=83\). T2: data bits at positions 3,5,6,7 are \(0,1,1,0\); \(p_1\) (3,5,7) \(=1\), \(p_2\) (3,6,7) \(=1\), \(p_4\) (5,6,7) \(=0\); word \(1100110\). T3: detect 5, correct 2.

One-Page Revision
  • BCD sum digit \(>9\) or carry \(\Rightarrow\) add 6. Excess-3 \(=\) BCD\(+3\). Gray: \(G=B\oplus(B\gg1)\).
  • Detect \(d_{\min}-1\); correct \(\lfloor (d_{\min}-1)/2\rfloor\). Parity: \(d_{\min}=2\).
  • Hamming: \(2^r\ge k+r+1\); syndrome gives error position; SECDED adds an overall parity bit.
  • CRC: append remainder of \(M\cdot x^m\bmod G\) (modulo-2 division).
